Web playground

Build a little website with scraps, in the Elm architecture. main.scrap is the app: the model to start with, init, the update of the model with each message that the site sends, and the view of the model that the site shows.

Each editor holds a draft, which refers to others by path, as $"./html.scrap". Once the updates settle, state.scrap holds the model, as a scrap: edit any draft, or the state itself, and the site keeps its state. The address bar keeps every draft, to share.

-- A little website, in the Elm architecture: the page shows the view of the
-- model, and each message that it sends updates the model, which
-- state.scrap holds. Edit any draft and the site reloads, keeping its state.
{ init, update, view }

; init = { draft = "", next = 3, todos = [todo 1 "Write a scrap", todo 2 "Click me to cross me off"] }
; todo = id -> text -> { id, text, done = #false }

; update =
  | #edit text -> m -> { ..m, draft = text }
  | #add -> m -> (m.draft |> | "" -> m | text -> { draft = "", next = m.next + 1, todos = m.todos +< todo m.next text })
  | #toggle id -> m -> { ..m, todos = list/map (t -> is id t |> | #true -> { ..t, done = not t.done } | #false -> t) m.todos }
  | #remove id -> m -> { ..m, todos = keep (t -> not (is id t)) m.todos }

; view = m -> h.div []
  [ h.style $"./style.scrap"
  , h.h1 [] [h.text "Todos"]
  , h.form [h.on "submit" #add]
    [ h.input [h.attr "value" m.draft, h.attr "placeholder" "What needs doing?", h.on-input (text -> #edit text)]
    , h.button [] [h.text "Add"]
    ]
  , h.ul [] (list/map item m.todos)
  , h.p [h.class "left"] [h.text (int/to-text (left m.todos) ++ " left")]
  ]
; item = t -> h.li [h.class (t.done |> | #true -> "done" | #false -> "")]
  [ h.span [h.on-click (#toggle t.id)] [h.text t.text]
  , h.button [h.on-click (#remove t.id)] [h.text "×"]
  ]

; is = id -> t -> int/cmp id t.id |> | #eq -> #true | _ -> #false
; not = | #true -> #false | #false -> #true
; left = list/fold 0 (n -> t -> t.done |> | #true -> n | #false -> n + 1)
; keep = f -> list/fold [] (kept -> t -> f t |> | #true -> kept +< t | #false -> kept)
; h = $"./html.scrap"
{ draft = "", next = 3, todos = [ { done = #false, id = 1, text = "Write a scrap" }, { done = #false, id = 2, text = "Click me to cross me off" } ] }
-- Helpers that make views, as Elm's Html does: an element takes its
-- attributes and its children.
{ el, text, attr, class, on, on-click, on-input
, div, h1, p, ul, li, span, form, button, input, style
}
; el = tag -> attrs -> children -> #el { tag, attrs, children }
; text = t -> #text t
; attr = name -> value -> #attr { name, value }
; class = attr "class"
; on = event -> msg -> #on { event, msg }
; on-click = on "click"
-- A function of the input's value makes the message.
; on-input = msg -> #on-value { event = "input", msg }
; div = el "div"
; h1 = el "h1"
; p = el "p"
; ul = el "ul"
; li = el "li"
; span = el "span"
; form = el "form"
; button = el "button"
; input = attrs -> el "input" attrs []
; style = css -> el "style" [] [text css]
-- The site's style sheet, which main.scrap puts in a style element.
text/join "\n"
  [ "body { font: 16px/1.5 system-ui, sans-serif; margin: 2rem; color: #22211e; }"
  , "h1 { margin: 0 0 1rem; }"
  , "form { display: flex; gap: .5rem; }"
  , "input { flex: 1; min-width: 0; font: inherit; padding: .3rem .5rem; }"
  , "button { font: inherit; cursor: pointer; }"
  , "ul { padding: 0; list-style: none; }"
  , "li { display: flex; justify-content: space-between; padding: .3rem 0; border-bottom: 1px solid #e2e0d8; }"
  , "li span { cursor: pointer; }"
  , "li.done span { text-decoration: line-through; color: #6b6960; }"
  , ".left { color: #6b6960; }"
  ]

        The type of an app
        
    An app has the type app model msg, for a model and messages of its choosing. A view is text, or an element with attributes, handlers of events that send a message, or a function of the value of the event's target that makes one, as an input's, and children.
    

    -- The web platform's contract: an app in the Elm architecture.
--
-- An app keeps its own model, of type model, which the host never inspects.
-- The host shows the page that `view` makes of the model, starting with
-- `init`, and passes `update` each message that the page sends, with the
-- model, for the next one.

app

; app   : type -> type -> type = model => msg => { init : model, update : msg -> model -> model, view : model -> html msg }
; html  : type -> type = msg => [#text text, #el { tag : text, attrs : list (attr msg), children : list (html msg) }]
; attr  : type -> type = msg => [#attr { name : text, value : text }, #on { event : text, msg : msg }, #on-value { event : text, msg : text -> msg }]
